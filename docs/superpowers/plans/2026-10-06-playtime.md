# Playtime Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Show platform-reported playtime per game in the Library (sort and label) and on Game detail.

**Architecture:** `RemoteGame.playtimeSeconds` flows from providers into `platform_game.playtime_seconds` (new migration), is summed per game in `library-store.ts`, and reaches the UI through the existing `LibraryGame` and `GameEntry` types. Sorting stays in the renderer.

**Tech Stack:** TypeScript, node:sqlite, zod, React, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-06-playtime-design.md`

## Global Constraints

- No code comments (project rule); Prettier no semicolons, single quotes; ESLint zero warnings.
- Providers are pure adapters (no SQL). Migrations are forward-only (`0009_playtime.sql`) with an upgrade test.
- `null` = platform does not report playtime; `0` = reported, none played. A `null` never overwrites a stored value.
- Playtime never announces anything and does not touch the baseline rule.
- Verified sources only: Steam (`playtime_forever` minutes, family `rt_playtime`), Epic (`totalTime` seconds), EA (`totalPlayTimeSeconds`). Ubisoft, Xbox, PlayStation, shadPS4, RPCS3 return `null`.
- Dashboard untouched.
